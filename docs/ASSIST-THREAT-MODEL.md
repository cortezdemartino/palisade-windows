# Windows Assist threat model

The inactive owned remote input peer now checks the actual helper certificate before native peer acceptance and forwards only a single bounded control channel. Deterministic tests refuse expired peer proof at admission, queued dispatch and late native acceptance even if the watchdog has not run. Pre-admission traffic is bounded and discarded. Real Electron negatives exercise certificate substitution, channel misuse, malformed traffic, native stalls, cancellation and renderer loss with a fake sink. The live coordinator must derive the helper binding from verified native grants, sign only its own transport statement, revoke native flags synchronously on close and retain cleanup through child exit. These are integration requirements, not permission supplied by the transport.

Status: **Experimental, inactive**, October 26, 2026. This is an implementation assessment with independent component review, not a product security audit. Production main/preload do not expose the native/capture components. Fully compromised local hosts with sufficient privileges are outside the claimed boundary.

A signature is not current authorization; encryption is not consent or peer identity. A checksum supplies integrity, not confidentiality. DPAPI protects storage for the current user, not against that user's compromised account. The named ownership object supplies exclusion, never permission; another local process may hold it to deny service.

The current live guardian protocol is diagnostic only. Its immediate-exit watchdog must not be reused as a live controller cleanup path. Future native IPC/gateway wiring must route teardown through the runtime and retain release-only cleanup. Issuer qualification now rejects first-use trust; release pin or explicit native out-of-band confirmation is required. Real consent, stop shortcut, input, lock/sleep, mixed DPI, transport encryption and cross-client acceptance remain required before activation.

Native bridge v1 adds exact schema/provenance checks, a live preload challenge, per-document event envelopes, cancellation outside the ordinary queue and one-shot source/peer terminal events. Tests cover stale signatures, reload, spoofed frames, full queues, late replacement events and exhausted lifecycle capacity. All four endpoint statement vectors are purpose-separated; a proof cannot substitute for a grant acknowledgement. Live enrollment tuple and actual observed remote certificate checks are still integration requirements. These component tests do not qualify the product against a compromised renderer.

The native enrollment tuple is now private, non-deserializable and bound to the locally confirmed installation/account/device/endpoint and qualified issuer. Native session admission cannot derive the publisher from an offered grant. Revocation/Drop invalidates registered sessions, and dispatch observes global stop through blocking intent and final shortcut steps. Tests use synthetic native approval and actual temporary DPAPI identity keys; real dialogs/input and the owned remote gateway remain unqualified. The page-side eight-request safety-queue defect and native resource/relay handoff are tracked in Windows#4.
