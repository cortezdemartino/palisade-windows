## Inventory and organization

Before: a 400-pixel overlay with General, Permissions, and Updates & What's New.
The last category also contained Assist status, installation history, diagnostics
and reload. Navigation scrolled with content; tabs had no roving focus or tab
semantics. Small descriptions and crowded rows reduced readability.

| Category now | Controls and information |
| --- | --- |
| General | Startup; tray behavior; explicit Close versus Quit explanation |
| Notifications & permissions | Notification test; fixed Windows notification/microphone links; account versus OS explanation |
| Updates | Installed/latest version; last successful check; download/progress/cancel/restart; pause/resume; three automatic preferences; installation history; optional Manager repair |
| What's new | Authenticated current/saved release summaries, dates, categories and details; offline/empty/missing-current states |
| About & support | Version, architecture/build/runtime; truthful Assist availability; reload confirmation; troubleshooting copy; fixed user-guide/support links |
| Account & workspaces | Instructions matching supported hosted navigation and a Return to Palisade action |

There is no settings migration. Existing tray/update/pause preferences and the
Windows startup preference retain their existing storage and defaults. Startup
remains off by default. Reversible switches apply immediately on this PC.

## Implementation

- `src/window-chrome.html`, `.css`, `.js`: up to 920-pixel Settings surface with
  persistent sidebar, independently scrolling content and visible close/footer.
  Narrow layouts use tab rows; very short enlarged-text layouts use a labelled
  category selector. Category and per-category scroll position survive reopening
  during the same app run. Minimum native window size is 640 by 440 DIP.
- The graphite surfaces, blue accent and spacing follow companion
  `docs/55-DESIGN-SYSTEM.md`. No new theme state or dependencies were introduced.
- Labelled switches, proper tab/panel associations, selected state, roving focus,
  arrows, Home/End, Tab/Shift+Tab loop, Enter/Space and Escape support improve
  keyboard access. Reopening focuses the category; closing restores the gear.
  Return to Palisade and fullscreen dismissal return focus to hosted content.
  Focus outlines, forced colors and reduced motion are supported.
- Updates retains the existing signed updater and safe restart behavior. Manager
  repair is behind Having trouble updating? Verified notes are separate and
  initially prefer the installed release when saved. They remain plain text.
- `src/desktop-window.cjs` and `src/window-controls-preload.cjs` retain exact
  sender/frame/URL checks and isolated sessions. Only fixed no-argument support
  and return actions were added; display fields remain bounded. No hosted
  navigation, arbitrary URL, file, process or permission API was added.
- `src/main.cjs`: tray prioritizes Open Palisade, relevant status, Updates,
  Settings and Quit. Active safety/Stop controls remain available. Inactive
  sharing and duplicate preference/test/Manager entries were removed. Native
  menus use matching category names. Reload asks before interrupting calls;
  repeated UI/menu reload requests share one confirmation. Save failures retain
  the previous preference and report failure. Troubleshooting copy reports
  completion, including repeated requests. The native Check for updates action
  opens Updates so its progress and result remain visible even when up to date.
- `tests/settings-persistence.test.cjs` adds older-settings/session preservation,
  invalid stored value and failed atomic replacement cases.
  `tests/desktop-window.test.cjs` covers fixed destinations, rejected hosted
  actions, save feedback, reload cancellation/deduplication and existing lifecycle.
- `scripts/settings-ux-smoke.cjs` joins the existing Electron runner. Windows CI
  uploads its screenshots and result JSON with the candidate installer.

## Preserved boundaries and remaining limits

Native Assist sources, frozen contracts/fixtures, settings format, updater
verification/installer rules, public keys, account/session storage, permission
policy and application identity were not changed. Public Assist remains disabled;
localYield and cross-client acceptance remain unqualified. Existing Close/tray,
Stop and quit/update cleanup behavior remains authoritative.

Not Verified in this UX pass:

- Actual Windows DPI changes, Narrator operation and Windows theme switching.
  The recorded zoom, media and accessibility-tree checks are emulations.
- A first-time-user usability study or exhaustive low-resolution/localized layouts.
- Actual toast acceptance under each Windows policy and OS permission changes;
  existing notification/URI fixtures cover dispatch without changing personal settings.
- Installed upgrade/restart, Matrix reauthentication and real Assist acceptance.
  Existing separate device/service/release gates still apply.

For manual acceptance, use an approved disposable Windows profile: open every
category with mouse and keyboard, toggle tray/startup/update preferences and
restart, inspect 100/150/200% Windows scaling, use Narrator for category and switch
names, test Windows contrast themes, check a real notification and OS links,
then confirm Close versus Quit and an authorized installed upgrade. Keep all
Assist production switches unchanged. No release or installation is authorized
by this UX checkpoint.
