# U1 signed release-note foundation

Starting Windows revision: `e534314cef83ee4d849980c02f833005fbd93f71`.
This is the first U1 implementation slice, not completion of the native updater.

## Implemented

- Separate domain-separated Ed25519 notes sidecar bound to the canonical v3
  installer payload, exact product/platform/channel/version/date and active signer.
- Strict bounded editorial input, release template, pre-packaging validation,
  signing and publication verification. Legacy release schemas and root are retained.
- Local Settings summary/details, publication date and history version selector.
  Bounded isolated IPC exposes presentation data only. Text-only rendering.
- Bounded display-only cache, signature revalidation and historical rotation rules.
  Unavailable notes never become unsigned GitHub prose or installer authority.
- Manager source integration, shared validators, authenticated v3 online/offline
  discovery, legacy fallback only on missing metadata and no packaged rotation floor,
  SHA-256 download verification, matching history UI and offline package filters.
- Downloader cancellation through transport, writes and final publication checks.
- A content-checked integration kit records the local non-Git Manager source changes
  in this repository. Its 18 recorded files match the maintained source. The
  existing published Manager executable and desktop pin are unchanged.

## Remaining U1 work and limits

The signed-notes foundation is Implemented and verified with automated tests and
real Windows UI execution. It is not installed-upgrade acceptance.

Desktop-owned staging, native helper identity/ACL/reparse protections, retained
parent handoff, safe apply/recovery, update preferences/progress and full lifecycle
tests remain unfinished. Routine installation still opens the existing Manager.
The old `install.ps1` remains excluded from packaging and must not be used as the
native handoff. The native helper must independently verify signed metadata and
the exact installer; Node verification alone is insufficient.

Installed upgrades, failure/recovery with a real installer, and a Manager-independent
installed update are Not Verified. They require approved disposable Windows devices.
No Assist activation, personal-device input testing, installation, deployment,
production release signing or publication occurred. Exact pushed-SHA CI is recorded
in the continuation checkpoint after the commit is pushed.
