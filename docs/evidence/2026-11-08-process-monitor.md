## Implementation

- `windows/process_tree.rs` creates an anonymous non-killing/no-breakaway job. The fixed verified helper image is locked while `CreateProcessW` atomically assigns its coordinator through `PROC_THREAD_ATTRIBUTE_JOB_LIST`. A strict handle list restricts inheritance; children receive a query-only job handle and SYNCHRONIZE-only terminal event. There is no unassigned-child fallback, arbitrary executable path, shell, terminating limit or job termination call.
- The direct application-owned `windows/process_monitor.rs` retains the exact coordinator and job handles, validates request/response correlation and launch challenges, signals stop on coordinator death before descendant waits, and waits for actual job accounting to reach zero after admission closes. A pre-launch scope guard signals stop on error/unwind even when detached threads retain handles. Output pressure and ordinary saturation cannot block that event.
- Private live version1 retains its existing channel-only behavior. An explicit trusted-main `ownedTree` option negotiates private version2 with `nativeInput: false` and `cleanupScope: channel-and-process-exit`. The monitor holds a matching channel terminal response until normal coordinator exit and complete process-tree exit. Crashes or malformed/missing proofs retain failed application lifecycle ownership.
- All new scheduling/descendant/stop-holder fixtures are probe-only, including when sensitive Cargo features compile. The default helper and production main/preload remain inactive; no issuer, enrollment, OS input, clipboard or file permission is introduced by this milestone. The existing web/native canonical protocol pins and updater trust remain unchanged.

Windows API basis: [atomic job and handle attributes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute), [job inheritance and non-killing lifetime](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [exact job accounting](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-queryinformationjobobject).

## Defects and failed attempts

- Initial compilation caught a missing generated Win32 access-right import; the correct generated namespace/feature was added. Strict checks later caught borrowed-handle API and explicit fixture process-wait ownership issues; those were corrected without disabling lints.
- Initial job tests incorrectly expected exactly one active process. Querying the test job identified Windows' additional console host. Tests now prove the retained process's exact job membership, require nonempty accounting while the known holder lives, and await actual zero after closure. They never infer cleanup from process names. Fixture event names use an atomic counter to avoid parallel timestamp collisions.
- Review found that coordinator death originally signaled stop after waiting for job zero, which could deadlock a stop-dependent survivor. The order is corrected, an unconditional early-exit guard is installed, and an actual stop-event-only survivor crash test now catches that ordering error.
- Attribute backing values were reordered to outlive the Windows attribute list, as required by the documented API. This is a source correction independent of the failure below.
- One earlier all-feature library process exited with `0xC0000409` after69 individual OK results and before its aggregate result. Its cause remains unconfirmed. Serial diagnostic, uncaptured parallel and subsequent normal complete runs passed. Ten cached pre-change64-test binary runs and ten current-binary runs excluding new groups did not reproduce it. This does not establish that the lifetime correction caused or fixed the fail-fast; its historical failure remains recorded. Full integrated-candidate review and platform acceptance must revisit any recurrence.
- One application run failed its old static channel-only scope expression after version-dependent scope validation was introduced. It now asserts exactly the two non-authorizing scopes, matching returned scope and nativeInput false; behavioral scope-substitution tests and the complete app suite pass.

## Remaining engineering and acceptance

Process exit is not evidence that injected input was released. Before authority, register each executor generation and its direct authenticated cleanup-receipt channel, bound to the launch, exact retained process identity, session and generation. Normal shutdown needs successful retained runtime/mirror cleanup and child exits; guardian-crash recovery needs the executor's positive release-complete receipt and actual exit. Losing both owners without evidence must remain unproven even at job zero. This milestone's proof cannot be broadened by changing a feature flag.

Continue the real persistent coordinator/runtime registry, enrollment/issuer and guarded native consent, capture/source binding and transport signing, fresh-grant/peer admission, native extension v2 resources and cooperative scheduling. The companion cooperative contract remains absent, so no incompatible temporary wire behavior is invented.
